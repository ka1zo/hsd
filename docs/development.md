# Разработка HSD

## Структура

- `cpp/include/hsd/` — публичные C++-модели, токенизатор и лексический индекс.
- `cpp/src/` — реализация C++.
- `cpp/python/` — тонкая граница pybind11 между Python и C++.
- `src/hsd/` — Python-пакет, обход и чтение файлов (`ingest.py`), разбиение (`chunking.py`), передача пачек в ядро (`search.py`), модель фрагмента (`models.py`) и CLI.
- `tests/cpp/`, `tests/python/` — проверки соответствующих частей.
- `docs/` — решения и инструкции.

Python-пакет собирает C++-расширение `_core` через scikit-build-core и pybind11. Отдельная CMake-сборка по умолчанию по-прежнему собирает ядро и CTest без Python-модуля. Для неё не требуется pybind11, но теперь требуется SQLCipher.

scikit-build-core — инструмент сборки с лицензией [Apache-2.0](https://github.com/scikit-build/scikit-build-core/blob/main/LICENSE); pybind11 — библиотека связывания с лицензией [BSD-3-Clause](https://github.com/pybind/pybind11/blob/master/LICENSE). Они нужны при сборке Python-пакета, а не для загрузки документов или запросов в сеть.

## Работа с зашифрованным индексом

```sh
.venv/bin/hsd index /path/to/documents --output /path/to/search.hsd
.venv/bin/hsd search /path/to/search.hsd "привет" --limit 5
.venv/bin/hsd delete-index /path/to/search.hsd
```

`index --output` запрашивает пароль и сохраняет фрагменты и пути в SQLCipher. С `--model-dir` он также вычисляет и сохраняет эмбеддинги; файлы модели и их хэши указаны в [описании модели](model.md). При повторном вызове с той же папкой и моделью обновляются только изменившиеся файлы; подробности — в [описании индекса](index-format.md). `search` запрашивает пароль при каждом запуске, считывает фрагменты из SQLCipher и строит лексические структуры в памяти. `delete-index` удаляет файл `.hsd` и его журнальные файлы; исходные документы не трогает. Пустой пароль отклоняется. При потере пароля индекс нужно удалить и построить заново.

Пароль можно передать в стандартный ввод с `--password-stdin` для автоматизированного запуска. Не используйте аргумент командной строки или переменную окружения для пароля. HSD не ведёт журнал текста, путей, запросов и паролей. Формат схемы имеет версию 3; старые индексы версий 1 и 2 читаются, а при следующей записи мигрируют в версии 3 и один раз полностью переиндексируются. Более новая версия и повреждение дают ошибку. Неверный пароль и повреждение могут проявляться одинаково на уровне SQLCipher. При записи изменившиеся фрагменты собираются в Python, а при открытии лексические структуры перестраиваются из базы; большой индекс может занимать заметную память.

Файл индекса использует штатные ключ, соль и KDF SQLCipher 4; HSD не реализует свою криптографию. Обычная SQLite не может прочитать базу. Включены временные таблицы в памяти, `journal_mode=DELETE` и `secure_delete=ON`; SQLCipher также шифрует журналы транзакций. HSD не создаёт незашифрованных временных баз или резервных копий. Шифрование индекса не распространяется на исходные документы, память работающего процесса и доступ пользователя к разблокированной системе.

## Гибридный поиск

Для сочетания словесного и смыслового поиска используйте `hsd search /path/to/search.hsd "запрос" --mode hybrid --model-dir /path/to/model --limit 5`. C++ объединяет позиции в ранжированных списках формулой RRF с константой 60. CLI показывает BM25, косинусное сходство и итоговую оценку RRF для каждого фрагмента. Воспроизводимый пример и ограничения метрик описаны в [методике оценки](evaluation.md).

## Векторный поиск

После индексации с `--model-dir` выполните `hsd search /path/to/search.hsd "запрос" --mode vector --model-dir /path/to/model --limit 5`. Режим загружает эмбеддинги и фрагменты из SQLCipher, вычисляет вектор запроса локально и передаёт его в C++ для полного сравнения по косинусному сходству. Размерность и L2-норма проверяются до поиска. Локальная модель должна совпадать с моделью индекса. Режим доступен для зашифрованного `.hsd` индекса; поиск по папке остаётся лексическим. Оценки BM25 и косинусного сходства имеют разные шкалы. Подробности — в [описании векторного поиска](vector-search.md).

## Поиск через CLI без сохранения

```sh
.venv/bin/hsd index /path/to/documents
.venv/bin/hsd search /path/to/documents "привет" --limit 5
```

На Windows замените `.venv/bin/` на `.venv\Scripts\`. Без `--output` команда `index` считает фрагменты во временном индексе и затем завершает работу; `search` с папкой строит такой же индекс, выполняет поиск по словам и выводит совпавшие фрагменты, путь, полуоткрытый диапазон байтов UTF-8 и оценку BM25. CLI выводит UTF-8, в том числе на Windows при системной кодировке `cp1252`. Документы и запросы не отправляются по сети. Символы управления в отображаемом тексте и пути экранируются. Обычный запуск после установки не требует сети; сама установка может загрузить инструменты сборки.

Передача Python → C++ идёт пачками по 256 фрагментов через `hsd.search.build_index`. Эта функция возвращает `hsd._core.LexicalIndex` в памяти. Ни CLI, ни Python-слой не рассчитывают оценки и не реализуют поиск повторно.

## Поиск по словам

`hsd::LexicalIndex::add_chunks(const std::vector<hsd::Chunk>&)` принимает пачку фрагментов в память. `search(query, limit)` ищет фрагменты, содержащие хотя бы одно слово запроса, и возвращает `SearchResult` с текстом, источником, диапазоном байтов и положительной оценкой BM25. Повтор слова в запросе не увеличивает оценку. При равной оценке результат упорядочен по пути и позиции. Неверный фрагмент или повреждённый UTF-8 отклоняется до изменения индекса этой пачкой. Лексические структуры существуют в памяти, а фрагменты могут храниться в SQLCipher.

Токенизатор приводит к нижнему регистру английские, основные русские и латинские буквы диапазона Latin-1; ASCII-цифры входят в слова. Поиск по словам пока не поддерживает другие письменности и сложную Unicode-нормализацию. Векторный режим помогает искать по смыслу, но не заменяет точные совпадения слов.

## Чтение документов

После установки пакета можно получить фрагменты прямо из Python:

```python
from pathlib import Path
from hsd.ingest import iter_chunks

for chunk in iter_chunks(Path("путь/к/документам")):
    print(chunk.source_path, chunk.start_byte, chunk.end_byte, chunk.text)
```

Функция проходит по `.txt`, `.md` и `.markdown` в предсказуемом порядке, пропускает символические ссылки и выдаёт фрагменты по мере чтения файлов. Позиции — полуоткрытый диапазон байтов `[start_byte, end_byte)` исходного UTF-8-файла. Пробелы по краям фрагментов опускаются; максимальная длина фрагмента — 800 символов, без перекрытия. Пустые файлы не дают фрагментов. Файл больше 8 МиБ, неверный UTF-8 или ошибка чтения останавливают обход с явным исключением без вывода содержимого файла. Эти ограничения можно задать аргументами `max_chars` и `max_file_bytes`.

Обход не защищает от одновременной подмены каталогов и ссылок другим процессом. Для обработки документов, которые может менять другой пользователь, сначала скопируйте их в отдельную папку с ограниченным доступом.

## Подготовка

Откройте корень папки HSD в IDE. Нужны Python 3.11+, CMake 3.20+, SQLCipher Community Edition 4.x и компилятор C++20 (Apple Clang, Clang, GCC либо MSVC). В CI сборка и тесты выполняются на macOS 15, Ubuntu 24.04 и Windows 2025 с Python 3.12. На локальном macOS ARM64 также использовались Python 3.13.5, Apple Clang 16.0, CMake 4.4.4 и SQLCipher 4.19.0.

### SQLCipher Community Edition

- **macOS:** `brew install sqlcipher`; Homebrew предоставляет заголовки и `sqlcipher.pc`. Проверенная локально версия: 4.19.0.
- **Linux:** соберите SQLCipher 4.x из [официального исходного кода](https://www.zetetic.net/sqlcipher/sqlcipher-linux-community/) с OpenSSL и опциями из официального руководства: `--with-tempstore=yes`, `-DSQLITE_HAS_CODEC`, `-DSQLITE_EXTRA_INIT=sqlcipher_extra_init`, `-DSQLITE_EXTRA_SHUTDOWN=sqlcipher_extra_shutdown`, `LDFLAGS=-lcrypto`. Затем установите библиотеку и сделайте `sqlcipher.pc` доступным через `PKG_CONFIG_PATH`. Нужны заголовки OpenSSL и инструменты сборки, указанные в руководстве. Дистрибутивный пакет допустим после проверки этих опций.
- **Windows:** установите SQLCipher Community Edition через [порт vcpkg](https://github.com/microsoft/vcpkg/tree/master/ports/sqlcipher) (`vcpkg install sqlcipher:x64-windows-static-md`) и передайте `-DCMAKE_TOOLCHAIN_FILE=ПУТЬ_К_VCPKG/scripts/buildsystems/vcpkg.cmake -DVCPKG_TARGET_TRIPLET=x64-windows-static-md` CMake и `CMAKE_ARGS` при установке Python-пакета. В `CMAKE_ARGS` используйте прямые косые черты в пути, чтобы парсер аргументов не удалил обратные. Порт собирает версию 4.6.1 из исходников с `SQLITE_HAS_CODEC`, `SQLITE_TEMP_STORE=2` и OpenSSL. Порт поддерживает только Windows; готовые бинарные пакеты Zetetic для Windows коммерческие.

CMake ищет `sqlcipher::sqlcipher` через конфигурацию пакета, затем `pkg-config sqlcipher`. При запуске HSD дополнительно проверяет `PRAGMA cipher_version`, так что обычная SQLite не будет принята. Для распространения бинарных сборок нужно включить [уведомление SQLCipher](https://github.com/sqlcipher/sqlcipher/blob/master/LICENSE.md) и [уведомление OpenSSL](https://github.com/openssl/openssl/blob/master/LICENSE.txt) вместе с уведомлениями прочих зависимостей. Открытая редакция SQLCipher распространяется по BSD-style лицензии, OpenSSL — Apache-2.0. Готовый установщик пока не выпускается.

Подробные шаги установки на macOS, Linux и Windows, включая SQLCipher и локальную ML-модель, находятся в [руководстве установки](install.md). Краткий путь из корня репозитория:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/hsd --help
```

На Windows замените `python3` на `py -3.11` или доступную версию 3.11+, а `.venv/bin/` на `.venv\Scripts\`. Установка Python-пакета не требует загрузки ML-модели. Среда установки пакета может обратиться к Python package index за scikit-build-core и pybind11; после установки обычный вызов CLI не использует сеть.

## Сборка и проверки

```sh
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
.venv/bin/python -m unittest discover -s tests/python -v
```

На Windows при генераторе Visual Studio добавьте `--config Debug` к `cmake --build` и `ctest`. Для проверки установленной команды выполните `.venv/bin/hsd --version` (Windows: `.venv\Scripts\hsd --version`).

## Отладка в VS Code

Установите расширения Python и C/C++ или CMake Tools. Выберите интерпретатор из `.venv`. Конфигурация `.vscode/launch.json` запускает `python -m hsd --help`. Точку останова можно поставить в `src/hsd/cli.py`.

Для C++ настройте CMake Tools на корень HSD, выберите установленный компилятор и конфигурацию Debug. Запустите `hsd_models_test` через CTest или отладчик IDE. VS Code не нужен для сборки или запуска программы.

## Безопасность файлов

Не добавляйте в Git свои документы, базы индекса, файлы модели и секреты. `.gitignore` содержит типовые каталоги и расширения, но перед коммитом всё равно проверяйте список новых файлов. Индекс содержит пользовательские данные в зашифрованном виде.
