# Обновление и восстановление индекса

Команда `hsd index FOLDER --output INDEX.hsd` сравнивает SHA-256 содержимого каждого поддерживаемого файла с записью в зашифрованном индексе. Неизменившиеся фрагменты и эмбеддинги остаются на месте; для добавленных и изменённых файлов выполняются разбиение и, если выбрана модель, локальный inference. Записи удалённых файлов удаляются из индекса. Команда возвращает общее число фрагментов.

Текущая версия формата SQLCipher — 3: в ней есть зашифрованные таблицы корня папки и контрольных сумм файлов. Индексы версий 1 и 2 можно читать. При первой повторной индексации они мигрируют и полностью пересчитываются, поскольку в прежнем формате контрольных сумм нет. Индекс с более новой версией отвергается без записи.

Изменения файлов, фрагментов и эмбеддингов записываются одной транзакцией. Ошибка чтения или кодировки, ошибка модели и сбой записи сохраняют прежние данные; следующий запуск может повторить обновление. Если состояние индекса изменилось между подготовкой фрагментов и транзакцией, обновление отклоняется с просьбой повторить команду. Для одного индекса требуется та же выбранная папка и та же модель. Чтобы перейти на другую модель или папку, создайте новый индекс.

При нарушении целостности SQLCipher либо метаданных HSD сообщает об ошибке и не пытается молча заменить данные. Повреждённую базу восстановить автоматически нельзя: при наличии исходных документов создайте новый индекс. SHA-256 проверяет, изменился ли файл, но каждый поддерживаемый файл всё равно читается при запуске. Снимок папки не блокируется: файлы, изменившиеся непосредственно во время обхода, могут потребовать повторного запуска.

Автоматические тесты покрывают добавление, изменение и удаление файлов, повторное использование эмбеддинга неизменённого файла, сохранение идентификатора его записи, откат транзакции при искусственно вызванном сбое SQL, восстановление после ошибки чтения, миграцию формата 2 и отклонение повреждённых метаданных.
